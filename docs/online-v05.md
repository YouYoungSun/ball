# v0.5 온라인 대전과 배포

온라인 게임은 Vite 프론트엔드와 별도 Node.js WebSocket 서버로 구성됩니다. 서버가 방과 플레이어를 관리하고 발사 명령을 검증하며 실제 게임 물리와 승패를 결정합니다. 한 방은 두 플레이어가 사용하고 관전은 지원하지 않습니다.

## 로컬 실행

Node.js 24에서 프로젝트 루트에 의존성을 설치하고 두 터미널에서 실행합니다.

```sh
npm ci
npm run server
```

```sh
npm run dev
```

서버 기본 포트는 8787입니다. 개발 프론트엔드는 기본적으로 로컬 서버에 연결합니다. 다른 주소를 사용하려면 Vite 실행 전에 `VITE_GAME_SERVER_URL`을 설정하세요. 예: `VITE_GAME_SERVER_URL=ws://localhost:8787 npm run dev`.

방을 만들고 6자리 코드를 상대에게 전달합니다. 상대가 입장한 후 양쪽이 준비하면 경기가 시작됩니다. 경기 후 양쪽이 재대결을 선택하면 새 경기가 시작됩니다. 일시적으로 연결이 끊기면 같은 브라우저 탭에서 재접속을 시도합니다.

## 운영 배포

1. 장시간 WebSocket 연결을 지원하는 호스팅에 이 프로젝트의 Node 서버를 배포합니다. `PORT`는 호스팅이 제공하는 값에 맞추며 기본값은 8787입니다. TLS를 종료하는 프록시를 사용해 공개 `wss://` 주소를 제공하고 WebSocket 업그레이드를 전달하도록 구성합니다.
   브라우저 접속을 제한하려면 서버 환경변수 `ALLOWED_ORIGINS`에 정확한 프론트엔드 Origin을 쉼표로 구분해 지정합니다. 예: `https://game.example.com,https://preview.example.com`. 미설정 시 모든 Origin을 허용하며 Origin 헤더가 없는 비브라우저 연결도 허용합니다.
2. Vercel에서 프로젝트 루트를 선택하고 Vite 프레임워크, 설치 명령 `npm ci`, 빌드 명령 `npm run build`, 출력 디렉터리 `dist`를 설정합니다.
3. Vercel 빌드 환경변수 `VITE_GAME_SERVER_URL`에 공개 WebSocket 주소를 지정하고 프론트엔드를 빌드·배포합니다. 이 값은 빌드 결과에 포함되므로 바꾸면 재배포가 필요합니다. HTTPS 페이지에서는 `wss://`를 사용하세요.
4. 배포 후 `https://서버주소/health`의 응답과 서로 다른 브라우저의 방 생성·입장·준비·발사·재접속·재대결을 확인합니다.

서버 주소를 운영 빌드에 지정하지 않으면 온라인 모드에 설정 오류가 표시됩니다. 실제 배포는 수행하지 않았습니다.

Docker를 이용하는 경우 예시는 다음과 같습니다.

```sh
docker build -t alkkagi-server .
docker run --rm -p 8787:8787 -e PORT=8787 alkkagi-server
```

컨테이너는 서버만 실행합니다. 프론트엔드는 별도로 빌드하고 호스팅해야 합니다.

## 상태와 제한

- 데이터베이스가 없으며 방과 세션은 서버 메모리에만 있습니다. 서버 재시작 시 모든 방과 진행 중인 게임이 사라집니다.
- 연결이 끊기면 30초 안에 같은 탭의 세션 토큰으로 재접속할 수 있습니다. 서버는 진행 중인 물리 시뮬레이션을 계속하며 새 발사는 두 플레이어가 연결된 경우에만 받습니다. 탭의 세션 정보가 사라지거나 서버가 재시작되면 복구할 수 없습니다.
- 30분 동안 활동이 없는 방은 정리됩니다. 플레이어가 명시적으로 방을 나가면 방이 종료됩니다.
- 이 구성은 단일 서버 프로세스 기준입니다. 여러 서버 인스턴스 간 방 상태 공유는 제공하지 않습니다.
- `/health`는 서버 상태와 현재 방 수를 JSON으로 반환합니다.
