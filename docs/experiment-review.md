# 연출 방향 실험 첫 검토

이 패키지는 새 출시 연출이 아니라 선택을 위한 실험이다. 기존 게임은 `/`, 비교 도구는 `/lab.html`이다. 채택 전까지 기존 게임 연출과 물리·온라인 규칙을 유지한다.

## 비교하는 세 방향

캡처 영상은 왼쪽부터 실물 A, 아케이드 B, 무협 C다. 실험실은 선입견을 줄이려고 순서를 무작위로 섞으므로 영상의 A/B/C와 버튼의 익명 A/B/C가 같다고 가정하지 않는다. 실험실의 '실제 방향 이름 보기'로 확인할 수 있다.

- 실물: 판은 유지하고 말을 다시 그려 눌림·기울기·접촉·접지로 힘을 표현한다. 큰 입자나 문자 없이 힘을 전달하려는 안이다.
- 아케이드: 준비의 기하학적 압축, 방향 레일, 실제 첫 접촉의 표시 좌표만 잠깐 고정하는 표현을 연결한다. 물리 tick은 멈추지 않는다.
- 무협: 실제 이동 경로의 먹선과 접촉점의 밝은 절단 획, 짧은 먹의 여운으로 한 수를 표현한다.

각 안은 독립 합성 효과음을 제공한다. 기본 실험 화면은 무음이며 '소리 켜기'로 활성화한다. 합성음이 좋다는 결론은 아직 내리지 않았다.

## 총괄의 관찰과 채택 상태

390px 개별 및 300px 3열 네이티브 프레임에서 준비와 접촉을 확인했다. 아케이드는 접촉 위치의 대비가 가장 명시적이지만 넓은 접촉면이 글자를 잠깐 가리는 문제가 있다. 무협은 경로가 기억되어 원인과 결과를 연결하지만, 긴 먹선이 얼마나 빠르게 정리돼야 하는지는 실제 반복 조작 평가가 필요하다. 실물 첫안은 피격 말의 옆면이 길어져 나무알이 기둥처럼 뜨는 문제가 관찰되어 한 차례 재작업했다.

우선 비교할 추천 순서는 아케이드, 무협, 실물이다. 이는 정지/시퀀스 프레임의 가독성에 관한 잠정 의견이며 손맛 순위나 최종 채택이 아니다. 세 방향을 기존 게임에 합쳐 넣지 않았다. 청취와 실제 조작, 반복 피로에 대한 합격 근거가 없으므로 계획서의 품질 점수와 식별률을 채우지 않는다.

## 이번 작업 방식에서 실제 달라진 점

1. 담당 기능별 완료 보고 대신, 각각 완성된 시청각 방향을 만들도록 했다. 세 감독은 서로의 후보 코드를 첫 제출 전에 읽지 않았다.
2. 비교 샷을 코어에서 먼저 기록했다. 후보가 더 강한 물리로 좋은 연출처럼 보이게 할 수 없다.
3. 장면의 실제 사건을 검사해 '가장자리 탈락' 장면이 빗나가 자멸하던 오류를 수정했다.
4. 첫 제출 뒤 실물 담당이 자신의 모바일 프레임에서 실패를 확인하고 재작업했다. 완료 보고만으로 채택하지 않았다.
5. 독립 QA가 동작 줄이기에서도 남던 낙하 애니메이션과 비동기 음향 초기화 경계를 점검했다.
6. 시각 후보 제시와 출시 통합을 분리했다. 실제 품질이 좋아졌는지 사용자 평가가 남아 있다.

확인된 것은 절차가 서로 다른 표현과 비교 가능한 자료를 만들었다는 점이다. 더 재미있는 게임이나 더 효율적인 제작 방식이 됐다는 결론은 아직 아니다. 작업 시간·반복 횟수·사용자 선택·선택안의 실제 대전 성능을 다음 단계에서 함께 기록해야 한다.

## 확인 방법

`npm ci` 후 `npm run dev`로 실행하고 터미널에 표시된 주소 뒤에 `/lab.html`을 붙인다. 중앙 일반/강타를 먼저 무음으로 보고, 후보를 바꿔 반복한다. 390px 표시로 전환하고 소리 켜기로 음향을 별도로 비교한다. 이후 경첩·가장자리·질량 차이 장면을 확인한다. 실험실은 녹화된 물리 장면을 조작하는 도구로, 자유롭게 겨냥하는 대전 화면은 아니다.

## 기술 검증과 미완료 항목

전체 62개 테스트와 프로덕션 빌드, 기존 음향 연결 검사가 통과했다. 코어·통신·서버·기존 화면과 음향 등 보호 파일 10개의 해시가 시작 시점과 같다. 신규 검사는 코어의 매 tick 재현, 후보 입력 불변, 효과 수명, 음소거와 예약음 취소를 포함한다.

영상은 네이티브 Canvas의 오프라인 렌더이며 무음이다. 실제 브라우저 조작, 스피커 청취, 모바일 기기 프레임 시간은 검증하지 않았다. 이에 따라 '모든 채택 조건 통과', '80점 이상', '강타 식별률 통과'라고 주장하지 않는다.
