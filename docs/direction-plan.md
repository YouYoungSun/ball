# 장기 알까기 연출 재설계 실행 계획

기준 버전: v0.6. 이번 목표는 기능 추가가 아니라, 일반 샷과 경기당 한 번의 강타를 실제로 쏘고 싶게 만드는 것이다. 기존 버전과 나란히 놓지 않으면 차이를 찾기 어려운 수정은 채택하지 않는다. 이 문서는 다음 서브에이전트 작업의 공통 지시서다. 현재 단계는 계획 수립이며 아래 실험은 아직 실행하지 않았다.

## 1. 무엇이 실패했으며 무엇을 바꿀 것인가

지금까지는 초기 속도, 잔상 길이, 작은 충돌 표식 등 개별 요소를 순차적으로 수정했다. 구현과 테스트는 쌓였지만, 사용자가 느끼는 발사와 충돌의 경험을 하나의 장면으로 설계하지 못했다. 새 모델이나 새 세션이 이 문제를 자동으로 해결하지 않는다.

다음 작업에서는 기존 코드의 효과 수치를 조절하는 것으로 출발하지 않는다. 먼저 각 감독이 준비→발사→접촉→피격→탈락의 흐름을 설계하고, 그중 가장 중요한 순간을 하나 정한다. 표현 방식이 충분히 다른 세 가지 장면을 만들어 비교한다. 기존의 '강타' 인장도 반드시 유지할 자산이 아니다.

성공의 목표 문장: **작은 화면에서도 내가 힘을 모아 쏘고, 어떤 말을 때렸으며, 그 결과가 무엇인지 즉시 읽힌다. 강타는 글씨를 읽기 전에 특별한 한 수로 느껴진다.**

## 2. 고정할 것과 과감히 바꿔도 되는 것

고정: v0.6 물리·질량·마찰·초기 속도·강타 1.25배·경기당 사용 횟수·경첩 위치·온라인 판정·상하 진영·현재 판의 표시 크기. 연출 때문에 기존에 살아남던 말이 죽거나, 같은 발사 결과가 달라지면 실패다.

자유: 조준 표현, 말의 시각적 자세와 표면 반응, 그림자, 이동 흔적, 국소 조명, 접촉 형태, 입자, 카메라의 짧은 반동, 시각적 멈춤, 연출용 시간 재생, 효과음 합성 및 재생 구조, 낙하와 결과 표시. 기존 view/audio 구현을 교체해도 된다. 소규모 수정량을 성과로 평가하지 않는다.

말의 시각적 기울기나 미세한 압축은 허용하지만, 실제 위치·크기·충돌 판정을 오해시키지 않아야 한다. 나무 장기판과 장기알의 정체성은 유지하되, 무조건 절제된 표현만 허용하는 조건은 없앤다. 첫 실험은 의도적으로 크게 표현하고, 읽기 어려운 부분을 나중에 줄일 수 있다.

금지: 물리 시간을 멈추는 연출, 상대에게 보이지 않는 판정 변화, 전체 화면을 덮는 긴 컷신, 반복 섬광, 상시 진동, 효과 범위를 실제 공격 범위처럼 오해시키는 가짜 광역 충격파. 필살기 글씨·음량·흔들림만 키운 안은 제출 요건을 충족하지 않는다.

## 3. 공통 실험 장면과 제출 형식

각 안은 같은 입력과 이벤트 기록을 재생한다. 물리가 달라서 더 강해 보이는 비교를 막는다. 비교 화면에는 후보 이름 대신 A/B/C를 사용하고 표시 순서를 바꾼다. 모델명·구현량은 선택 근거에서 제외한다.

### 대표 장면

1. 조준 준비부터 첫 충돌의 여운까지 약 3초로 구성한 중앙 졸 강타. 실제 물리 진행 시간을 늘리거나 줄이지 않는다. 조준 준비는 표시용 입력 기록으로 만든다.
2. 같은 방향의 일반 샷. 강타와 일반 타격의 차이를 확인한다.
3. 무거운 말이 가벼운 말을 치는 샷과 가벼운 말이 무거운 말을 치는 샷. 무게의 차이가 효과에 묻히지 않아야 한다.
4. 경첩 반사 후 충돌. 금속 접촉과 나무 접촉을 구분하고 경로를 읽을 수 있어야 한다.
5. 가장자리 탈락 및 마지막 말 탈락. 충돌→낙하→결과의 순서를 확인한다.
6. 약한 접촉, 빗나감, 연쇄 충돌. 약타가 과장되거나 실제로 없던 성공을 연출하지 않아야 한다.

첫 비교는 1과 2에 집중한다. 후보 선택 후 3~6으로 일반화한다. 모든 장면을 먼저 늘려 놓고 핵심 장면을 덜 다듬지 않는다.

### 모든 후보의 필수 산출물

- 조준부터 결과까지 사건별 연출 의도를 적은 짧은 타임라인. 시간값은 가설로 표시한다.
- 실제 코드로 동작하는 대표 장면. 정지 목업만 제출할 수 없다.
- 같은 크기·속도·샷으로 만든 일반/강타 유음 영상과 무음 영상. 음량 비교는 동일한 재생 조건에서 한다.
- 모바일 390px 안팎과 데스크톱 표시에서의 전체 판 영상. 확대된 충돌 부분만으로 합격시키지 않는다.
- 키보드/마우스로 반복 발사하고 후보를 바꿀 수 있는 로컬 연출 실험 화면. 다시 보기와 음소거 제공.
- 바꾼 것, 예상 효과, 직접 확인한 것, 아직 확인하지 못한 것. 스스로 '재미있다'는 평가를 검증 결과로 쓰지 않는다.

네이티브 Canvas 렌더는 방향 비교에 사용할 수 있다. 실제 브라우저 조작·음성 청취를 대체했다고 보고하지 않는다. 유음 기록을 만들 수 없으면 음향 검증은 미완료로 남긴다.

## 4. 서로 다른 세 가지 감독안

세 안은 같은 효과를 색상만 바꾼 변형이어서는 안 된다. 각 감독은 아래 의도를 자신의 방식으로 구체화하고, 최소 한 가지 기존 표현을 버린다.

| 안 | 중심 감각 | 반드시 보여줄 차이 | 실패 징후 |
| --- | --- | --- | --- |
| A 묵직한 실물 타격 | 손가락으로 나무알을 세게 튕긴 감각 | 조준의 긴장, 짧고 단단한 접촉, 질량별 반응과 재질음 | 어둡고 둔한 저음만 남거나 모든 말이 돌덩이처럼 보임 |
| B 과감한 아케이드 | 적은 순간에 힘을 몰아주는 쾌감 | 선명한 준비와 방출, 국소적인 시각적 멈춤, 피격 방향과 탈락의 강한 대비 | 판이 가려지거나 효과가 물리보다 먼저 성공을 선언함 |
| C 장기와 무협의 한 수 | 장기알이 짧은 무술 동작처럼 읽히는 개성 | 먹선·서체·동세를 활용한 일관된 발사부터 접촉까지의 표현 | 붓선과 한자 장식만 붙고 타격의 리듬은 기존과 같음 |

세 감독 모두 독립적으로 시각과 임시 음향을 묶어 제출한다. 최종 음향 담당은 후보를 보기 전에 모든 안에 같은 소리를 덮어씌우지 않는다. 실험 중 새 효과음을 만들 수 있으며, 외부 서비스 연결은 필수가 아니다.

## 5. 채택 기준과 즉시 탈락 기준

### 먼저 통과해야 할 조건

- 같은 명령의 최종 위치·생존 상태·턴·스킬 소비가 v0.6과 동일하다.
- 무음·모바일 표시에서 강타와 일반 샷이 구분된다. 글자 표시를 숨겨도 차이가 남는다.
- 소리만 들었을 때 약타·강타·낙하의 역할이 섞이지 않는다. 실제 청취 없이는 이 항목에 합격 표시를 하지 않는다.
- 접촉 위치, 피격 방향, 떨어진 말이 읽힌다. 화면이 더 화려해져도 결과를 이해하기 어려워지면 탈락한다.
- 연쇄 충돌에서 모든 접촉을 최대 효과로 재생하지 않는다. 중요한 충돌의 소리와 시각 효과가 다른 효과에 묻히지 않는다.
- 재접속·새 경기·음소거에서 과거의 효과나 승리음이 다시 나오지 않는다.
- 60Hz 목표 기기에서 연출 때문에 지속적인 끊김이 생기지 않는다. 실제 측정 기기와 프레임 시간을 기록하고 미측정 항목은 남긴다. 흔들림 끄기와 동작 줄이기 설정을 존중한다.

첫 관찰에서는 강타/일반 5개 짧은 클립의 순서를 섞어 구분 가능성을 확인한다. 4개 이상 식별을 임시 목표로 삼되, 소수의 관찰을 통계적 품질 증명으로 취급하지 않는다. 식별 가능성과 재미는 따로 판단한다.

### 선행 조건을 통과한 안의 비교표

| 항목 | 배점 | 판단 질문 |
| --- | --- | --- |
| 발사와 접촉의 만족감 | 30 | 같은 샷을 다시 쏘고 싶은가? |
| 힘과 무게의 전달 | 20 | 작은 말·큰 말·일반·강타의 차이가 읽히는가? |
| 행동과 결과의 연결 | 20 | 어디에 맞아서 무엇이 날아갔는지 한 번에 이해되는가? |
| 장기 알까기만의 개성 | 15 | 다른 게임의 흔한 폭발 효과로 대체해도 똑같지 않은가? |
| 반복 피로와 화면 가독성 | 15 | 열 번 반복해도 시끄럽거나 답답하지 않은가? |

합계 80점을 초기 채택 목표로 사용한다. 단, 실제로 관찰하지 않은 항목에는 점수를 채우지 않는다. 사용자 반응이 '여전히 비슷하다'이면 점수와 관계없이 미채택이다. 규칙·온라인 회귀 통과는 필수 조건일 뿐 미적 점수에 가산하지 않는다.

즉시 재작업: 인장이나 효과 이름만 더 눈에 띔, 음량만 큼, 전체 흔들림만 증가, 차이를 보려면 느린 재생이나 확대가 필요함, 정지 이미지에서만 멋있음, 모델이 스스로 좋다고 했다는 이유만 있음.

## 6. 에이전트 구성과 지휘 방식

| 역할 | 모델 배정 | 책임과 권한 |
| --- | --- | --- |
| 총괄 감독 | 현재 Astra | 공통 장면과 기준 확정, 중간 거절, 최종 비교와 통합 책임 |
| A 감독 겸 구현자 | Astra | 실물 타격 방향을 독립 구현 |
| B 감독 겸 구현자 | Astra | 아케이드 방향을 독립 구현 |
| C 감독 겸 구현자 | Astra | 장기·무협 방향을 독립 구현 |
| 통합 및 음향 개발 | 6.1 | 선택안의 시청각 타이밍, 클라이언트 표시시간과 서버 판정 분리 |
| 독립 검증 | 6.1 | 결과 불변·재접속·중복 효과·성능 검사, 연출안 작성에 참여하지 않음 |
| 캡처와 패키징 | Terra | 동일 조건 녹화, 파일 정리, 비교 자료 제작. 미적 선택권은 없음 |

동시에 모두 실행하지 않는다. 공통 실험 도구를 먼저 만들고, A/B/C를 병렬 실행한 다음, 선택안에 통합·검증·패키징 담당을 투입한다. 새 세션은 서로의 안에 영향을 덜 받게 하는 수단이며 창의성의 근거가 아니다.

공통 파일 충돌 방지: 먼저 현 view/audio API와 후보 선택용 진입점을 정한다. 각 감독은 분리된 후보 디렉터리 또는 독립 체크아웃에서 구현한다. core/net/server는 읽기 전용이다. main.ts의 조준 표시·연출 타임라인 연결은 총괄이 소유한다. 모델들이 동시에 같은 table.ts를 덮어쓰지 않는다.

감독에게 기존 연출 수치를 정답처럼 전달하지 않는다. 대신 필수 제약·공통 장면·실패 기준을 준다. 첫 결과가 미미하면 파티클 수치를 조금 올리라고 지시하지 않고, 준비와 방출 또는 접촉의 표현 원리를 바꾸라고 돌려보낸다.

## 7. 실제 작업 순서와 중단 지점

1. **공통 실험 도구:** v0.6 기준 보관, 동일 명령/이벤트 기록, 후보 전환·반복·무음 기능 구현. 현 상태를 그대로 재현하는지 확인한다.
2. **감독별 장면 설계:** 세 감독이 사건 타임라인과 자신이 버릴 기존 요소를 제시한다. 방향이 겹치면 구현 전에 재배정한다.
3. **대표 장면 구현:** 일반 샷과 강타 두 장면을 먼저 완성한다. 이 단계에서는 출시 ZIP을 만들지 않는다.
4. **총괄의 1차 탈락 심사:** 모바일·무음·동일 음량·반복 재생으로 확인한다. 선행 조건 미달은 사용자에게 추천안으로 올리지 않는다. 채택할 안이 없으면 '없음'으로 보고한다.
5. **전후 비교 제시:** 통과한 서로 다른 안만 짧은 영상과 직접 조작 화면으로 제시한다. 추천 이유와 부족한 점을 함께 말한다. 아직 청취하지 못했으면 음향 완성으로 주장하지 않는다.
6. **선택과 통합:** 사용자 반응을 반영해 하나를 주된 연출 언어로 선택한다. 다른 안의 요소는 역할이 명확하고 충돌하지 않을 때만 이식한다. 세 안의 모든 효과를 합치지 않는다.
7. **나머지 상황 확장:** 질량 차이·경첩·탈락·연쇄·빗나감에 적용하고 실제 두 기기 대전을 검증한다.
8. **최종 패키징:** 선택안, 기준 버전 복귀 방법, 변경 목록, 실제 검증 범위를 포함해 제공한다.

후보별 최초 구현과 한 차례의 방향 수정까지를 첫 실험 묶음으로 삼는다. 그 뒤에도 차이가 미미하면 출시 번호만 올리지 않고 방향 설계를 다시 한다. 반복 횟수는 품질 합격을 대신하지 않는다.

## 8. 다음 에이전트에게 그대로 전달할 지시문

당신의 목표는 지정된 연출 방향으로 장기 알까기의 일반 샷과 강타를 서로 다른 손맛으로 표현하는 것이다. 기존 코드의 작은 수치 수정에 머물 필요가 없다. 조준의 긴장부터 발사, 접촉, 피격의 여운까지 하나의 흐름을 설계하고 직접 구현하라. 첫 실험은 충분히 과감하게 만들 수 있다.

v0.6 물리와 온라인 규칙, 판의 크기와 위치는 변경하지 마라. 같은 샷의 결과는 완전히 같아야 한다. 화면을 가리는 장시간 컷신, 실제 범위로 오해되는 광역 효과, 글씨·음량·흔들림만으로 강타를 구분하는 안은 허용하지 않는다.

지정된 후보 작업 공간만 수정하라. 다른 후보 코드는 첫 제출 전 읽지 마라. 구현 전에 사건 타임라인과 버릴 기존 표현 하나를 적어라. 동일 장면의 일반/강타, 모바일/데스크톱, 유음/무음 비교와 반복 조작 가능한 결과를 제출하라. 이미지 한 장, 테스트 통과 보고, 자신이 좋다고 느낀다는 문장만으로 완료하지 마라.

실제로 본 것·들은 것·측정한 것과 코드에서 추정한 것을 구분하라. 필요한 API 변경은 총괄에게 요청하라. 판정 시간을 바꾸지 말고 표시용 연출 시간을 사용하라. 연출 지연 중 다음 입력이 열리거나 온라인 효과가 중복되지 않도록 통합 담당에게 필요한 계약을 명시하라.

총괄은 제출물을 탈락시킬 수 있다. 미미한 차이를 성공으로 포장하지 않는 것이 이번 작업의 공통 기준이다.
