# 개발자 검토: 솔로에서 PvP로

## 결론

현재 게임 코어와 화면은 PvP에 재사용할 수 있습니다. 플레이 가능한 솔로와 한 기기 대전을 구현했고 통신 경계를 마련했습니다. 온라인 연결까지 완성했다는 뜻은 아닙니다.

장기알 업데이트에서도 물성·경첩은 같은 코어의 고정 tick에서 판정합니다. 새 룰 버전은 `janggi-alkkagi-2`이며 v0.1 체크포인트와 섞지 않습니다. 32알과 경첩의 상태 복원 검사를 추가했습니다.

## 현재 데이터 흐름

사람의 드래그 또는 AI 탐색 → 정수로 양자화한 `ShotCommand` → 코어의 차례·소유권·힘·중복 검증 → 고정 tick 물리 → 게임 사건 → 화면·소리.

명령에는 경기 ID, 규칙 버전, 수 번호, 발사 ID, side, 돌 ID, 정수 impulse가 있습니다. 호스트는 접속 세션에 할당한 side와 명령의 side를 대조해야 합니다. 접속자가 보낸 side를 신원으로 믿으면 안 됩니다.

## 불변 원칙

1. 물리 계산은 `Game.stepFixed()`만 수행합니다. 코어에는 DOM, 시간 조회, 네트워크, 연출 랜덤이 없습니다.
2. 화면·소리·흔들림은 코어 상태를 변경하지 않습니다.
3. 돌 중심이 판 밖으로 나가면 코어에서 탈락을 확정하고 충돌에서 비활성화합니다. 낙하 높이·회전은 화면이 처리합니다.
4. 생존 돌이 연속 30 ticks 동안 낮은 속도이거나 최대 샷 tick에 도달하면 턴을 확정합니다. 애니메이션/오디오 끝을 판정 근거로 삼지 않습니다.
5. 스냅샷은 Rapier 바이트뿐 아니라 turn, side, phase, 승패, rest 카운터, 중복 발사 집합, 샷 로그를 포함합니다.
6. top-down 무중력 환경에서 collider friction만으로 판 마찰이 생기지 않으므로 선형 감쇠를 명시합니다.

## 온라인 첫 단계: 친구 초대

- 호스트가 판정 권한을 가집니다.
- 게스트가 명령을 보냅니다. 호스트는 접속별 side와 현재 턴을 검사해 ACK/거부를 반환합니다.
- 양쪽에서 같은 샷을 재생하고, 턴 경계에서 호스트 체크포인트와 해시로 확인합니다.
- 불일치는 호스트 체크포인트로 복구합니다. turn/tick/shotId 중복과 순서를 관리해야 합니다.
- 현재 `LoopbackTransport`/`HostAuthority`는 프로토콜 경계와 로컬 하네스용입니다. 실제 UI의 네트워크 세션은 아직 연결하지 않았습니다.

## DB 없이 가능한 범위

친구끼리 한 판을 유지하는 동안 상태는 호스트 메모리에 둘 수 있습니다. WebRTC 연결을 위한 offer/answer와 ICE 후보 교환(signaling)은 별도로 필요합니다. 편한 방 코드는 그 코드에 대응하는 만료형 상태를 연결 서비스에서 전달해야 합니다. 직접 연결이 막힐 때 TURN 중계도 고려해야 합니다.

Vercel은 현재 WebSocket을 지원하지만 연결은 함수 최대 수명과 인스턴스에 묶입니다. 두 접속·재접속이 같은 함수에 도달한다는 보장이 없으므로 함수 메모리 변수 하나로 안정적인 방 서비스를 만들지 않습니다. Vercel은 프런트 배포에 사용하고, signaling/공유 상태 경로는 온라인 단계에서 선택합니다.

영속 전적과 계정은 DB 없이 생략할 수 있습니다. 호스트가 사라진 뒤의 경기 복구, 랭킹, 공식 경쟁전은 다른 요구사항입니다. 호스트 권위는 호스트 치트를 막지 못하므로 공식 경쟁전에는 서버에서 같은 코어를 실행하는 권위 서버가 필요합니다.

## 검증한 것

- 한 프로세스의 독립 코어 두 개가 같은 명령으로 같은 물리 바이트와 상태를 생성함.
- 움직이는 도중의 체크포인트 복원과 이후 결과 일치.
- 샷 로그의 여러 턴 재생.
- 효과 사건을 읽거나 버려도 결과 일치.
- 다른 경기/룰/턴/소유돌, 정수가 아닌 힘, 범위를 벗어난 힘, 중복 발사 거부.
- 빠른 정면 충돌 감지, 탈락 후 승패, 동시 마지막 탈락 무승부.
- 루프백 하네스의 명령 전달 → 호스트 side 검증 → ACK → 최종 체크포인트 → 게스트 복원.

이 검증은 인터넷 전송과 실제 브라우저 간 동기화 검증이 아닙니다. 원격 입력의 완전한 runtime schema 검증과 데이터 크기 제한, 연결 복구, 지연/재전송/중복/끊김 테스트는 온라인 작업 범위로 남습니다.
